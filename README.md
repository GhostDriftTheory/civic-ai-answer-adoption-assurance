# 自治体AI・回答採用アシュアランス｜公開技術PoC 第1弾

**AIの回答案を、根拠と業務上の条件に照らして「採用できる・確認が必要・採用できない」に分け、その理由を後から確かめる。**

株式会社クラウドシエンと株式会社AIアシュアランスが、自治体業務へのAI活用に向けて取り組む技術検証（PoC）の公開参照実装です。クラウドシエンは自治体業務・導入要件の整理、AIアシュアランスは技術設計・実装・検証を担います。

架空の制度・補助金案内を例に、回答の対象自治体、資料の版・期間、相談条件、金額、根拠との対応を検査します。入力条件や根拠が足りなければ保留し、不整合があれば採用を止めます。条件を満たした回答案だけを職員の確認用に出力し、判定に使った情報と理由を保存します。

「業務要求パケット」は、回答案の採用に必要な条件をまとめた情報です。「責任情報パケット」は、入力、適用した条件・資料、判定、根拠、未確認事項、利用範囲を結び付けた検証記録です。

本リポジトリには、外部通信のない操作デモ・Python実装と、OpenAI APIが実際に生成した回答を評価した2026年10月11日の実験記録を収録しています。使用する制度・資料・相談者はすべて架空・合成データです。実自治体への導入、行政上の決定、第三者認証を示すものではありません。

- [操作デモ](https://ghostdrifttheory.github.io/civic-ai-answer-adoption-assurance/civic_ai_poc_demo.html)：通常案内、条件不足、不整合の違いをブラウザ内で確認できます。外部通信はありません。
- [実API実験レポート](https://ghostdrifttheory.github.io/civic-ai-answer-adoption-assurance/report.html)：24件の原回答、採用判定、根拠、人工的な誤りを加えた試験を確認できます。

HTMLファイルを保存してブラウザで開くこともできます。保存応答の再検証には `openai_answer_eval.py` を使用します。

## まず実行する

このフォルダでターミナルを開いて、次を実行してください。

```console
python poc.py
```

Windowsで `python` が見つからず、Python Launcherが利用できる場合は `py poc.py`、macOS/Linuxでは環境に応じて `python3 poc.py` を使います。Python自体が必要です。追加パッケージのインストールやAPIキー、サーバー起動は不要です。

実行後、画面に表示される `output/run-実行時刻-識別子/report.html` をブラウザで開いてください。**最初は「01 まず代表ケースを見る」だけ見れば十分です。** 正常案内がPASS、条件・根拠不足がHOLD、不整合がREJECTになることと、その理由を確認できます。

## 最初の実行で起きること

通常実行では、代表6ケース、参考30ケース、補完後2ケースを評価し、計38件の責任情報パケットを保存します。それぞれをディスクから読み直して再検証し、回帰・異常入力・変更検出の自己テストも実行します。

| 代表ケース | 判定 | 何が起きるか |
|---|---|---|
| 通常の案内 | PASS | 職員が確認する回答案として採用可 |
| 相談条件が不足 | HOLD | 従業員数・市税滞納の有無を追加確認 |
| 自治体が違う | REJECT | 依頼と回答の対象不一致を検出 |
| 古い資料 | REJECT | 固定の採用対象版・期間との不一致を検出 |
| 根拠が不足 | HOLD | 金額が合っていても、根拠との対応がなければ保留 |
| 上限額が不一致 | REJECT | 回答60万円と資料30万円の不一致を検出 |

補完では、合成の従業員数・滞納有無、または金額の根拠参照を追加し、HOLDからPASSへ変わることを確認します。補完前の記録を残し、補完後の記録に前件パケットIDと変更内容を含めます。これは実住民への確認や、確認者の本人認証ではありません。

**PASSは補助金の受給・採択決定ではありません。** 「対象外という案内」が入力条件と根拠に整合する場合も、正しい案内の回答案としてPASSになります。受給可否の判定と、案内文を採用してよいかの判定は別です。

## ブラウザとPythonの相互再検証

`civic_ai_poc_demo.html` はPythonとは独立して、ブラウザ内で同じ採用条件を検査します。PythonとのHTTP接続はありません。判定処理・参照資料・ケース・JSON再検証は、検証基準の `civic_ai_poc_demo.html` と同じです。表示文と説明文だけを公開向けに整えています。

Pythonの結果を操作デモHTMLで確認するには、操作デモHTMLを開き、**「要求と証拠」→「JSONを読み込む」**から、`packets/` 内のJSONを選びます。内容識別値、要求仕様、再計算した判定と根拠の一致が表示されます。

注意：操作デモHTMLのJSON読み込みは、読み込んだ記録の「再検証結果」を表示する機能です。画面上部で選択している代表ケースや回答文を、読み込んだ入力へ切り替える機能ではありません。Python側の一覧と内訳は、生成された `report.html` で確認してください。

逆に、操作デモHTMLで保存した対応形式のJSONも、次のコマンドでPythonから再検証できます。

```console
python poc.py verify "保存したパケット.json"
```

Python側では操作デモHTMLの通常記録を受理したうえで、重複JSONキー、実在しない日付、値の型、保証範囲の書換えなどを追加検査します。異常な入力についてまで操作デモHTMLと同じ受理挙動を約束するものではありません。

## よく使う操作

```console
# 全ケースを実行
python poc.py

# 条件不足の代表ケースだけを実行
python poc.py run --case missing

# CASE-IDでも選択可能
python poc.py run --case CASE-04

# 合成条件の補完前・補完後を確認
python poc.py complete missing

# 根拠参照の補完前・補完後を確認
python poc.py complete unsupported

# output内に保存した全パケットを再検証
python poc.py verify output

# 自己テストだけ実行
python poc.py test

# 任意の出力先を指定
python poc.py --out my_results
```

代表ケースのキーは `normal`、`missing`、`wrong_city`、`stale`、`unsupported`、`inflated` です。

通常のケース判定がHOLDやREJECTでも、所定の期待結果に一致して処理が正常終了すれば終了コードは0です。再検証不成立やテスト不一致は1、入力・ファイル・設定エラーは2です。入力エラーをPASSやHOLDに読み替えません。

## 業務要求と検査範囲

R01：対象自治体・制度の一致。R02：資料の版・募集期間。R03：相談条件と案内の対応。R04：回答中の主張と根拠。R05：必須条件・断定の抑制。R06：データ区分・処理設定。R07：利用範囲・人間による確定。R08：主張・資料・記録の同一性。

`REJECT > HOLD > PASS` の優先順で集約し、不整合が1件でもあればREJECT、不足だけならHOLD、全条件を通過したときだけPASSです。

R06は合成データ区分や処理設定の照合です。`synthetic: true` という申告だけで実際の個人情報が含まれないと証明するものではありません。実際の個人情報検出・匿名化・利用目的の法的評価は、このPoCに実装していません。

## ダミーデータを変更する

`cases.json` の `scenarios` と `tests` は、`base_input` に対する差分です。`changes` で既存の入力項目を置き換えます。回答文は構造化主張から固定テンプレートで生成されます。

例えば、次のようなケースを追加できます。

```json
{
  "key": "employees_21_wrong",
  "label": "従業員21人なのに対象候補と案内",
  "expected": "REJECT",
  "changes": {
    "id": "CASE-07",
    "label": "従業員21人なのに対象候補と案内",
    "applicant.employees": 21
  }
}
```

`expected` は評価結果との比較にのみ使い、採用判定の計算には使いません。既存の代表6ケースや補完定義は残してください。

`requirements`、`source_catalog`、`claim_metadata` は操作デモHTMLと同じ信頼基準として、Python内の参照SHA-256で固定しています。そこを変更したデータは起動時に拒否します。制度・条件・参照資料の差替えは、単なる入力ケースの編集とは区別します。実制度や別制度への移行では、資料・抽出条件・テンプレート・検査仕様をまとめてレビューする必要があります。

JSONの数値は安全整数域の整数と、0～1・小数2桁までの補助率に限定しています。従業員数の真偽値、重複ID、不正日付、未知の主張、NaN、Infinity、重複JSONキーは拒否します。これは汎用JSON正規化規格の完全実装ではありません。

## 再検証が意味すること・意味しないこと

再検証では、内容ハッシュ、固定の要求仕様、入力から再計算した判定と根拠、未確認事項・利用範囲の記録が一致するかを確認します。HOLD・REJECTも、正しく再現できれば「再検証成立」です。採用可への変更ではありません。

SHA-256は電子署名ではありません。時刻はローカルPCの時計で、時刻認証を付けていません。固定参照値は、受け取ったパケット自身の申告を信頼基準にしないためのもので、本Python自体の改変を防ぐものではありません。正当なコードと参照仕様の版を信頼して実行する必要があります。

補完履歴には前件IDを含めますが、第三者の署名付き承認、前件からのあらゆる変更の自動監査、履歴全体の完全性の証明は実装していません。

## 検証範囲

`poc.py` は、**架空の制度情報・合成相談者・AI回答を模した構造化回答候補によるローカルPoC**です。実際の生成AIへの接続、実在の自治体資料、自然言語からの汎用的な条件抽出、実住民の属性確認、行政上の採択決定、住民への自動送信、個人情報保護の実運用保証は対象外です。

### 何を確かめる実験か

24ケースを実行前に固定し、OpenAI Responses APIへ各1回送信します。通常・対象外案内6件、入力や資料の不足6件、資料の版・改変・期間境界6件、未信頼メモによる誘導や業務条件6件です。使用する人物・制度・資料はすべて合成データで、実住民情報・顧客資料・非公開規則は送信しません。

**APIが生成した `answer` 原文を、そのまま保存・検査します。原文を正しいテンプレートで置き換えてPASSさせる実験ではありません。** 原文から自治体・制度・金額・補助率・期限・対象区分・必須条件・断定を取り出し、モデルが提示した出典・版・引用本文と照合します。引用が欠けていれば、参照値を自動補完して採用可能にすることはしません。

全文を確実に対応付けるため、この実験では、**7行の限定日本語文法**を指定します。値・対象区分・出典はAIが提示資料から選びます。単位は円／万円、補助率は百分率／分数を扱います。前置き、未定義の言い換え、追加の主張など、全文を解析できない回答はHOLDです。これは任意の自由文の意味全体を理解・証明する仕組みではありません。この限定は公開PoCの評価範囲であり、技術体系全体の適用範囲を限定するものではありません。

採用エンジンへ渡す際には、原文から得た値を内部の構造化表現へ射影します。その表現には固定テンプレートを用いますが、**これは内部計算用であり、API原文そのものの証明記録と混同しません。** 採用ファイルに出すのは全文対応・引用照合・8条件を通過したAPI原文だけです。

R06の外部通信なしという条件は、ローカルの判定処理についてのものです。API生成段階は別の明示的な通信境界であり、実験全体を「外部通信なし」と説明しません。許可した合成入力と固定エンドポイントだけを使用します。

### 誤採用だけでなく「使える回答を採用できるか」も測る

結果を次の2群に分け、件数を合算してAI実験回数とは表現しません。

- **未改変のAPI原回答**：24回の応答、原文のPASS／HOLD／REJECT、全文解析数、仕様上の誤採用、単純な値だけの比較との差を記録します。未完了・拒否・解析不能・未実行も残します。判定結果を見て回答を生成し直すことはしません。
- **人工的な誤り注入**：原回答がPASSしたものに限り、金額・率・期限・自治体・受給断定・必須条件・引用欠落・参照版・引用本文・未解析追記の10種類を加えます。親回答・変更内容・変更後の原文を残し、APIの自然な誤答とは別に評価します。対象が0件なら耐性を確認できたとは扱いません。

正解基準は、`Engine.evaluate` の判定をコピーせず、固定の制度事実・条件を別の参照判定で計算します。ただし原文パーサー等は共通であり、独立した第三者の人手評価や汎用的な言語正解判定ではありません。範囲外の原文は `UNSCORABLE` とし、判定一致率の分母から外し、その件数自体を示します。

事前の品質基準は、全24応答の取得、通常群で3件以上の原文採用、原文解析率75%以上、評価可能な原回答の仕様判定との一致、誤採用0件、10種類の人工試験の実施と全件非採用です。**全件HOLD／REJECTだけでは、品質基準を満たしません。** 検証の成功（記録を再計算できること）と、実験の品質基準達成は分けて表示します。

「値だけの比較」は金額・率・期限・自治体だけを見る本実験内の簡易比較です。他社製品・業界標準との性能比較ではありません。24の選定された合成ケースや派生試験から、実運用の事故率・全AIの正答率・法令適合を推定しません。

### 操作（Windows）

`openai_answer_eval.py` は `poc.py` と同じフォルダに置きます。Python以外の追加パッケージは不要です。フォルダ移動が難しい場合は、`py "実際のフォルダ\openai_answer_eval.py" ...` のようにフルパスで実行しても動きます。以下はファイルのあるフォルダでの例です。

```powershell
# 無料：24ケースと料金評価の表示。APIキー不要・通信なし
py openai_answer_eval.py live

# 有料：事前に固定した24ケースを1回ずつ実行
py openai_answer_eval.py live --execute
```

キーが環境変数 `OPENAI_API_KEY` にない場合は、プログラムが**非表示入力**で尋ねます。手元のキーを貼り付けてEnterを押してください。キーをチャット・GitHub・スクリーンショットに出す必要はありません。キーそのものは証拠ファイルへ保存しません。

接続確認だけを先に行うには `live --smoke --execute` を使えます（1回）。これは本実験と別の試行として残り、本実験24回の成功には数えません。接続確認は任意です。

失敗時は再実行を急がず、保存先とエラーを確認してください。実行前の計画・呼出し意図、取得できた応答を保存し、タイムアウト等では未確定として停止します。自動リトライ・自動再開・「PASSになるまで再生成」はありません。

出力先は毎回別の `output/answer-api-日時-識別子/` です。

```text
answer_api_evidence.json  # 実行前計画・応答・原文・判定・人工試験・集計を1本に結合
report.html              # 結果を見る。JSONから再生成可能
drafts/API-01.txt       # PASSしたAPI原文だけ。内容は書き換えない
```

実際には `drafts/` は同じ実行フォルダ直下に作成されます。以下の `実行フォルダ` は、実行後に表示されるパスへ置き換えます。

```powershell
# 無料：保存原文・判定・集計・レポート・採用ファイルを再計算
py openai_answer_eval.py verify "実行フォルダ"

# 無料：公開用の証拠2ファイルを、正しいフォルダ構造のZIPにする
py openai_answer_eval.py publish "実行フォルダ"
```

`publish` は証拠JSONとレポートを `evidence/openai-answer-api/実行ID/` の構造でZIPにまとめます。アップロードは行いません。`ci` の自動探索対象は、この `evidence/openai-answer-api/` 配下です。リポジトリ直下に収録した公表記録の検査には、上記の `verify .` を使います。記録のJSONとHTMLを改変せず保存する必要があります。

### 形式検証と自動検査

Leanモデルは8条件の集約、7種類の主張、許可操作、記録の再検証、回答案の出力条件などを定義し、45の名前付き定理を収録しています。条件不足・不整合を含む回答を採用しないこと、再検証がHOLD・REJECTをPASSに変えないことなどを扱います。

GitHub ActionsではPythonの入力・資料から観測値を組み立て、Leanで計算した条件・主張・判定・許可操作と照合します。Pythonの結論をそのままLeanの入力へ渡す方式ではありません。8条件の判定集約6,561通りと、書換えを含む記録の照合も検査します。

`lean_samples` は、原文評価で得た構造化入力、引用等の境界判定、採用判定を具体的なLean照合命題へ渡します。オフライン試験に加え、`evidence/openai-answer-api/` 配下に記録がある場合は、その記録も対象にします。`python openai_answer_eval.py ci` も同じ範囲を探索します。リポジトリ直下の公表記録は、`python openai_answer_eval.py verify .` で別途再検証します。APIキーは使用せず、外部APIを呼びません。証明は小さなバッチで検査し、未証明の穴や独自公理を認めません。

```console
# Lean/Elanを導入した環境でモデルを検査
lake update
lake build
```

**形式証明の対象はLeanの判定モデルです。** 原文パーサー、引用抽出、観測値の抽出、API通信、JSON解析・正規化、SHA-256、ファイル入出力、Python全体の全入力に対する正しさを証明したものではありません。Pythonとブラウザの通常操作は、実行時にLeanを呼び出す方式ではありません。
